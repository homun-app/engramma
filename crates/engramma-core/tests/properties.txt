# L'inventario delle proprietà proptest della suite (v0.6.6, F2).
# Una riga per proprietà, TRE colonne:
#   1. il file del test (dalla root del workspace);
#   2. il nome della funzione dentro il blocco `proptest!`;
#   3. (v0.6.14, N3) i MODULI che la proprietà esercita, percorsi dalla
#      root, separati da virgole: la mappa che dice se una proprietà è
#      TOCCATA — dalla base della fase è cambiato uno di questi file,
#      oppure il suo file di test (il suo oracolo). `scripts/caccia.sh`
#      la legge e dà il budget lungo alle toccate; una mappa larga costa
#      tempo di caccia, una stretta fa girare poco il codice cambiato.
#      Da questa fase ogni proprietà ha anche un corpo
#      `fn <nome>_body(seed: u64)` nel suo file: il seme è la
#      riproduzione deterministica (scripts/seme-sul-tag.sh).
# `properties_inventory` (tests/properties_inventory.rs) legge questo file,
# trova le proprietà nei sorgenti e confronta i due elenchi nei due sensi:
# togliere una proprietà diventa una modifica visibile qui, dove il
# revisore la legge. Controlla anche la terza colonna: ogni proprietà ha
# la sua mappa, e ogni percorso esiste. `scripts/caccia.sh` prende da qui
# le proprietà della caccia.
# Che cosa NON vede il parser: le proprietà generate da macro diverse da
# `proptest!`, e i blocchi annidati dentro un'altra macro (dettagli nel
# REPORT della fase).
